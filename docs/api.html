Check struct

carries Eq, Debug

The bounds a value must satisfy.

The names avoid min and max, which mean different things in the four
targets: least and most are the closed bounds, under and over the
open ones (JSON Schema's exclusiveMinimum and exclusiveMaximum).
shortest and longest bound a string's characters and a list's items
alike, which is how every one of the four spells it too.

  • least : Double?
  • most : Double?
  • over : Double?
  • under : Double?
  • step : Double?
  • shortest : Int32?
  • longest : Int32?
  • pattern : String?
  • format : String?
  • options : Array[@json.Json]
  • distinct : Bool
  • unique : Bool
fn Check::is_empty(Self) -> Bool

Whether anything is bounded at all, which is how a projection decides to
write nothing rather than an empty object.

fn Check::new(least? : Double, most? : Double, over? : Double, under? : Double, step? : Double, shortest? : Int32, longest? : Int32, pattern? : String, format? : String, options? : Array[@json.Json], distinct? : Bool, unique? : Bool) -> Self

A Check by name, so a caller states the one bound it means.

Field struct

carries Eq, Debug

One field of a model.

required and nullable are two questions, not one. The first asks
whether the key has to be there, the second whether its value may be null.
JSON Schema keeps them apart (required is a list on the object, null is
a type), SQL's NOT NULL is the second alone, and GraphQL's ! is both at
once. Folding them into one field would leave at least one projection
guessing.

  • name : String
  • kind : Type
  • required : Bool
  • nullable : Bool
  • doc : String
  • default : @json.Json?
  • check : Check
fn Field::new(String, Type, required? : Bool, nullable? : Bool, doc? : String, default? : @json.Json, check? : Check) -> Self

A field. Required by default, because a type whose fields are all optional
describes almost nothing, and because every one of the four targets treats
"present" as the ordinary case.

Layout struct

carries Eq, Debug

A value as a byte format lays it out.

A document says what a value is. A format that writes bytes also fixes how
wide it is, whether it carries a sign, which byte comes first, and whether
it is written where it stands or as an offset to somewhere else. The four
belong to the type rather than to the value: every value of the type is
laid out the same way, and a reader has to know before it looks at one.

A projection that writes a document reads kind and says nothing about the
rest, because a document has no width and no offset. The width alone is
still worth writing as a format, which is how the JSON family already
distinguishes int32 from int64.

  • kind : Type
  • bits : Int32?
  • unsigned : Bool
  • order : Order
  • reference : Bool
fn Layout::format(Self) -> String?

The format this layout asks for: int8, uint16, float32.

None when the layout fixes no width of its own, or when the kind is not
a number — a width on anything else is not a width, and writing one would
make a reader think the format had said something it did not.

fn Layout::new(Type, bits? : Int32, unsigned? : Bool, order? : Order, reference? : Bool) -> Self

A layout: the kind, and how a format writes it.

Every part but the kind has the common answer as its default, so a format
whose numbers are little-endian and written in place says only the width.

Order enum

carries Eq, Debug

Which end of a number comes first.

  • Little
  • Big

    Most significant byte first, which is what a network order is.

Type enum

carries Eq, Debug

What a value is, in the smallest set all four projections recognise.

Ref names another model rather than nesting it, so two models may point
at each other and a projection decides for itself whether to inline or to
emit a reference — $ref in JSON Schema, a foreign key in SQL, a named
type in SDL.

  • Bool
  • Int

    A 32-bit integer.

  • Big

    A 64-bit integer. Separate from Int because SQL and GraphQL both care
    which one, and because JSON numbers past 2^53 do not survive a double.

  • Real
  • Text
  • Bytes
  • Stamp

    A moment in time. Only a format that defines one reads into this; see
    Check::format for the other case, where a date is a string being
    checked rather than a date being parsed.

  • List(Type)
  • Dict(Type)

    A mapping with text keys. SQL and GraphQL have no such thing, and say so
    in their own way.

  • Ref(String)

    Another model, by name.

  • Nest(Model)

    Another model, written here. For the one that has no name of its own and
    so cannot be referred to; a named one belongs in Ref so that the
    projections can hoist it and point at it once.

  • Wire(Layout)

    A value as a byte format lays it out: its kind, and a width, a sign, a
    byte order and a reference mark that a document has no word for.

    The kind inside is what a document projection writes; the four layout
    facts are read by the projection that writes bytes, and by anything that
    has to agree with a peer on the shape of a message.

  • Any

    Anything at all: JSON Schema's empty schema.

  • Raw(@json.Json)

    A schema written out in full, for what this vocabulary cannot say —
    allOf, a vocabulary of one's own, a dialect's extension. Each
    projection either passes it through as it stands or reports that it
    cannot carry it. Reach for it last: nothing reads inside it.

fn Type::of_word(String) -> Self?

The type a word stands for, when it is one of the words word writes.

Read the suffixes from the right first: uint16-be-ref is a uint16 in
big-endian order, written by reference. A word fixes what the kind and the
width agree on, so a layout that contradicts its own kind — an Int at 64
bits — is written at the width it states and read back as the kind that
width belongs to.

fn Type::word(Self) -> String?

The word a scalar type is written with: what #model.field(kind=…) takes,
and what a report calls it.

None for a type with parts inside — a list, a mapping, a model, a schema
written out — because one word cannot carry what is in it. A layout's word
adds -be for a big-endian number and -ref for one written by reference;
both are read back by of_word, so a word and a type round-trip.

fn document(@moonmodel.Model, known? : Array[@moonmodel.Model], draft? : String) -> @moonbitlang/core/json.Json

A whole document: the model, and every model it mentions, under $defs.

known is where the referenced models are looked up. One that is missing
is left as a dangling $ref rather than refused — a schema that names a
type defined elsewhere is ordinary, and this package cannot know whether
the reader has it.

fn of(@moonmodel.Model, at? : String, draft? : String, title? : Bool) -> @moonbitlang/core/json.Json

A model as a JSON Schema object.

at is the prefix a Ref is resolved against, so the same model can be
written into a bare document or into one component of an OpenAPI file by
changing one argument rather than by rewriting the schema.

draft writes the $schema line. Left out there is none, which is what a
fragment wants; a whole document should say which dialect it is.

moonmodel/verify

a verdict on an instance

values

fn faults(@moonmodel.Model, @json.Json, known? : Array[@moonmodel.Model]) -> Array[@moonschema.Fault] raise

Every reason the instance does not conform, in the order the walk found
them; empty when it does.

A fault says where in the instance it happened and which keyword refused
it, so a caller can answer with the field's name rather than with "no".

fn schema(@moonmodel.Model, known? : Array[@moonmodel.Model]) -> @moonschema.Schema raise

The model as a schema a reader can check instances against.

A description is not a validator and does not become one here: it is
written out as JSON Schema 2020-12 — the form the projections already agree
on — and handed to something that knows the specification. What an instance
is checked against is therefore the schema this library publishes, not a
second opinion about it.

known is where the models a Ref names are looked up, and one that is
missing is refused by name: a document that points at a model it does not
carry cannot be checked, and quietly refusing every instance would blame
the instance for it.

Reading a description that is not a schema at all — a Raw that says
something no draft defines — raises too. Both are defects in the
description, which is a different thing from an instance that does not
conform.

fn valid(@moonmodel.Model, @json.Json, known? : Array[@moonmodel.Model]) -> Bool raise

Whether an instance conforms.

One call reads the schema and checks one instance. Checking many is worth
holding the Schema from schema instead, which reads the description
once.

types

Refused suberror

Why a description could not be read as a schema.

  • Missing(name~ : String)

    A model the description names, which the call did not hand over.

    A reference the document cannot resolve is not an instance that fails to
    conform; refusing here keeps the two apart, because a validator asked
    about an unresolvable $ref can only answer "no" to everything.
