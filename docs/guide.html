Install

One command adds the description and its projections. A program that wants OpenAPI does not link the SQL writer — the packages are separate on purpose.

moon add moonbitstack/moonmodel

In moon.pkg, import the root package and only the projections you need:

import {
  "moonbitstack/moonmodel",
  "moonbitstack/moonmodel/json",
}

The #model annotations are read at build time by cmd/derive. If you use them, add the rule to moon.mod and a dev_build to the package, or write the model with Model::new at run time instead.

Describe once

A struct carries its own description. Nothing is written twice: the JSON Schema, the OpenAPI object, the CREATE TABLE and the GraphQL type all come from the same value.

#model.derive(doc="somebody with an account")
pub struct User {
  #model.field(unique=true)
  id : Int64
  #model.field(longest="64")
  name : String
  age : Int32?
  home : Address
}

#model.derive
pub struct Address {
  city : String
}

User::describe() returns a Model — data, with nothing hidden behind it — so the same value can be written by hand, at run time or from a generator:

let user = @moonmodel.Model::new(
  "User",
  [
    @moonmodel.Field::new("id", Big, check=@moonmodel.Check::new(unique=true)),
    @moonmodel.Field::new("name", Text, check=@moonmodel.Check::new(longest=64)),
    @moonmodel.Field::new("age", Int, required=false, nullable=true),
    @moonmodel.Field::new("home", Ref("Address")),
  ],
  doc="somebody with an account",
)

let address = @moonmodel.Model::new("Address", [
  @moonmodel.Field::new("city", Text),
])

Annotations

A field with no annotation is named after itself and required. T? may be left out and may be null. Array[T] is a list, Map[String, T] a dictionary, an annotated struct a reference.

AnnotationGoes onMeans
#model.derivea structgenerate T::describe(); name= and doc= set the model's name and text
#model.derivean enuma field of this type is text limited to its constructors
#model.fielda fieldeverything below
#model.skipa fieldleave it out
#model.field keyMeans
name, docthe field's name in the model, and its text
kindthe type when the field's own says nothing: bool int big real text bytes stamp any, or a width — int16 uint64 float32
modelthe type is the model of this name
required, nullableoverride what the type says — two separate questions
defaulta default, read by the field's type
least, most, over, under, stepnumeric bounds, as strings
shortest, longestthe length of text or a list
pattern, formata text field's shape
optionone allowed value, repeated
distinct, uniquea list's items differ; no two records share the value

Four projections

Every projection takes the same value. A projection that cannot carry a field says so — it never invents a shape for it or fails.

JSON Schema 2020-12 is the projection that loses least: a 64-bit integer is format: int64, an optional-and-nullable field is a union with null, and a field that names another model is a reference.

assert_eq(@json.of(user), {
  "type": "object",
  "title": "User",
  "description": "somebody with an account",
  "properties": {
    "id": { "type": "integer", "format": "int64" },
    "name": { "type": "string", "maxLength": 64 },
    "age": { "type": ["integer", "null"], "format": "int32" },
    "home": { "$ref": "#/$defs/Address" },
  },
  "required": ["id", "name", "home"],
})

An OpenAPI 3.0 Schema Object says the same in its own dialect: nullability is a keyword rather than a type, and a reference points into the components.

assert_eq(@open.of(user, dialect=@open.Dialect::OpenApi30), {
  "type": "object",
  "title": "User",
  "description": "somebody with an account",
  "properties": {
    "id": { "type": "integer", "format": "int64" },
    "name": { "type": "string", "maxLength": 64 },
    "age": { "type": "integer", "format": "int32", "nullable": true },
    "home": { "$ref": "#/components/schemas/Address" },
  },
  "required": ["id", "name", "home"],
})

SQL keeps the columns and drops the rest: a field that names another model needs its own table, so home is reported rather than quietly turned into text.

assert_eq(@sql.table(user, dialect=@sql.Dialect::Postgres), (
  #|CREATE TABLE User (
  #|  id BIGINT NOT NULL UNIQUE,
  #|  name TEXT NOT NULL CHECK (length(name) <= 64),
  #|  age INTEGER
  #|)
))

GraphQL has no 64-bit integer — its Int is 32 bits by specification — so id is carried as a String, and ! folds "required" and "not null" into one mark.

let (sdl, skipped) = @sdl.of(user)
assert_eq(sdl, (
  #|"""
  #|somebody with an account
  #|"""
  #|type User {
  #|  id: String!
  #|  name: String!
  #|  age: Int
  #|  home: Address!
  #|}
))
assert_eq(skipped.length(), 0)

Checking an instance

The description is what an instance is checked against, written out as JSON Schema and read by a validator that knows the specification — so the schema a reader sees and the schema a request is held to are the same one.

let checker = @verify.schema(user, known=[address]) catch {
  error => abort("the description is not a schema: \{error}")
}
let good : Json = { "id": 1, "name": "ada", "home": { "city": "Kyoto" } }
let no_id : Json = { "name": "ada", "home": { "city": "Kyoto" } }
assert_eq(checker.valid(good), true)
assert_eq(checker.valid(no_id), false)
let faults = checker.faults(no_id)
assert_eq(faults[0].keyword, "required")
CallAnswers
schema(model, known=…)the model as a Schema, with every model it refers to
valid(model, instance, known=…)whether the instance conforms
faults(model, instance, known=…)every reason it does not, each with at and the keyword that refused it

What each projection cannot carry

Folding the losses into one number would hide which shape a reader gets. Each projection reports what it dropped, and the reason.

ProjectionCannot carry
JSON Schemaunique, which is about the collection; a layout's byte order and reference mark
OpenAPI 2.0nullable has no keyword — written as x-nullable; an open bound is a boolean beside the closed one
SQLDict, Nest and Ref need their own table; List is a column only in Postgres; Any and Raw have no type
GraphQLDict, Nest, Any, Raw have no type; no bound reaches the schema; a 64-bit number becomes a String
