Install

One command adds the description and its projections. A program that wants OpenAPI does not link the SQL writer — the packages are separate on purpose.

moon add moonbitstack/moonmodel

In moon.pkg, import the root package and only the projections you need:

import {
  "moonbitstack/moonmodel",
  "moonbitstack/moonmodel/json",
}

The #model annotations are read at build time by cmd/derive. If you use them, add the rule to moon.mod and a dev_build to the package, or write the model with Model::new at run time instead.

Describe once

A struct carries its own description. Nothing is written twice: the JSON Schema, the OpenAPI object, the CREATE TABLE and the GraphQL type all come from the same value.

#model.derive(doc="somebody with an account")
pub struct User {
  #model.field(unique=true)
  id : Int64
  #model.field(longest="64")
  name : String
  age : Int32?
  home : Address
}

#model.derive
pub struct Address {
  city : String
}

Annotations

A field with no annotation is named after itself and required. T? may be left out and may be null. Array[T] is a list, Map[String, T] a dictionary, an annotated struct a reference.

Four projections

Every projection takes the same value. A projection that cannot carry a field says so — it never invents a shape for it or fails.

// JSON Schema 2020-12
println(@json.of(User::describe()).stringify(indent=2))

// an OpenAPI Schema Object, three dialects
println(@open.of(User::describe(), dialect=@open.OpenApi30).stringify(indent=2))

// columns and CREATE TABLE, three dialects
println(@sql.table(User::describe(), dialect=@sql.Postgres))

// GraphQL SDL
let (sdl, skipped) = @sdl.of(User::describe())

See the showcase for the complete output of a model that uses every type and every check.

Checking an instance

The description is what an instance is checked against, written out as JSON Schema and read by a validator that knows the specification — so the schema a reader sees and the schema a request is held to are the same one.

fn conforms(user : Json) -> Bool {
  let checker = @verify.schema(User::describe(), known=[Address::describe()]) catch {
    _ => return false
  }
  checker.valid(user)
}
CallAnswers
schema(model, known=…)the model as a Schema, with every model it refers to
valid(model, instance, known=…)whether the instance conforms
faults(model, instance, known=…)every reason it does not, each with at and the keyword that refused it

What each projection cannot carry

Folding the losses into one number would hide which shape a reader gets. Each projection reports what it dropped, and the reason.

ProjectionCannot carry
JSON Schemaunique, which is about the collection; a layout's byte order and reference mark
OpenAPI 2.0nullable has no keyword — written as x-nullable; an open bound is a boolean beside the closed one
SQLDict, Nest and Ref need their own table; List is a column only in Postgres; Any and Raw have no type
GraphQLDict, Nest, Any, Raw have no type; no bound reaches the schema; a 64-bit number becomes a String
