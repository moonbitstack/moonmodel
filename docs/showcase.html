the description

The description answers questions about itself — how many fields, which are required, what it refers to — before any projection runs.

model      Customer — somebody with an account
fields     16
required   id, name, email, balance, active, joined, tier, tags, labels, home, billed_to, either, counter
mentions   Address
email      format email
preset     empty: true

JSON Schema 2020-12

A model that refers to another writes a $ref; the schema is the document's own vocabulary.

{
  "type": "object",
  "title": "Order",
  "properties": {
    "buyer": {
      "$ref": "#/$defs/Customer"
    },
    "total": {
      "type": "number"
    }
  },
  "required": [
    "buyer",
    "total"
  ]
}

the three OpenAPI dialects

Nullable, an open bound and a reference are spelled differently in 3.1, 3.0 and 2.0 — the same description, three ways.

OpenAPI 3.1 — references point at #/components/schemas/
{
  "type": "object",
  "title": "Probe",
  "properties": {
    "score": {
      "type": [
        "number",
        "null"
      ],
      "exclusiveMinimum": 0
    },
    "home": {
      "$ref": "#/components/schemas/Address"
    }
  },
  "required": [
    "score",
    "home"
  ]
}

OpenAPI 3.0 — references point at #/components/schemas/
{
  "type": "object",
  "title": "Probe",
  "properties": {
    "score": {
      "type": "number",
      "minimum": 0,
      "exclusiveMinimum": true,
      "nullable": true
    },
    "home": {
      "$ref": "#/components/schemas/Address"
    }
  },
  "required": [
    "score",
    "home"
  ]
}

Swagger 2.0 — references point at #/definitions/
{
  "type": "object",
  "title": "Probe",
  "properties": {
    "score": {
      "type": "number",
      "minimum": 0,
      "exclusiveMinimum": true,
      "x-nullable": true
    },
    "home": {
      "$ref": "#/definitions/Address"
    }
  },
  "required": [
    "score",
    "home"
  ]
}

2.0 keeps them under definitions:

        }

SQL, three dialects

SQL loses the most, so it returns both halves: the columns it wrote and the fields it could not.

SQLite    10 columns, 6 fields without one
Postgres  11 columns, 5 fields without one
MySQL     10 columns, 6 fields without one

CREATE TABLE customers (
  id BIGINT NOT NULL UNIQUE,
  name TEXT NOT NULL CHECK (length(name) <= 64 AND length(name) >= 1),
  email TEXT NOT NULL,
  age INTEGER CHECK (age >= 0 AND age < 150),
  balance DOUBLE PRECISION NOT NULL DEFAULT 0 CHECK (balance > -1000),
  active BOOLEAN NOT NULL DEFAULT TRUE,
  joined TIMESTAMPTZ NOT NULL,
  avatar BYTEA,
  tier TEXT NOT NULL DEFAULT 'free' CHECK (tier IN ('free', 'paid', 'staff')),
  tags TEXT[] NOT NULL CHECK (length(tags) <= 10),
  counter SMALLINT NOT NULL
)

no column for labels: a mapping with open keys needs its own table
no column for home: a reference to Address is a foreign key, which needs that table's key
no column for billed_to: a nested model needs its own table
no column for notes: anything at all has no column type
no column for either: a schema written out by hand has no column type

GraphQL SDL

GraphQL folds required and nullable into one !, and has no type for a mapping, a nested model, Any or Raw.

"""
somebody with an account
"""
type Customer {
  "assigned at sign-up, never reused"
  id: String!
  "what to call them"
  name: String!
  email: String!
  age: Int
  balance: Float!
  active: Boolean!
  joined: DateTime!
  avatar: Base64
  tier: String!
  tags: [String!]!
  home: Address!
  "a count a byte format writes in two bytes"
  counter: Int!
}

no type for labels: a mapping with open keys has no GraphQL type; declare a list of pairs
no type for billed_to: every GraphQL type is named; give this model a name and refer to it
no type for notes: anything at all has no GraphQL type
no type for either: a schema written out by hand has no GraphQL type

an argument type is the same shape under the other keyword:
input Address {
  line: String!
  city: String!
  country: String!
}
